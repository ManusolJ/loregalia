# Decisions

Agents: if a task depends on an **Open** decision, stop and ask. Do not choose. When a human decides
one, move it to Decided, with the date.

| D-19 | A show's status is set separately from its seasons                       | A show works before its seasons are known                                               | 2026-11-05 |
| D-20 | TVmaze for shows, not TMDB                                               | Seasons, no key, and images may be cached indefinitely                                  | 2026-11-05 |
| D-22 | Approve `ureq`, `serde` and `serde_json` in `crates/core`                | Blocking HTTP with timeouts for providers, and JSON mapping at the provider edge         | 2026-11-05 |
| D-23 | Approve `tempfile` as a dev-dependency only                            | Replaces four copies of a test helper across two crates; never ships in the app          | 2026-11-05 |
| D-10 | IGDB for games, through the Loregalia relay; a user's own Twitch credentials go straight to IGDB | Covers every platform. Steam's and GOG's store endpoints are unofficial, Steam's subscriber agreement bans automated access, and Epic blocks them | 2026-11-07 |
| D-11 | The app ships no keys. A small Loregalia relay holds the project's TMDB and IGDB keys, and users may enter their own keys, which bypass the relay | No setup for users, and the IGDB secret never leaves the server | 2026-11-07 |
| D-24 | Build the relay in Rust                                                  | The same language as the app, so it can share types and provider code with `core`        | 2026-11-07 |
| D-25 | Loregalia stays free; an optional Ko-fi link may go in About, never tied to a feature or to metadata | Keeps the app non-commercial under TMDB's and IGDB's terms | 2026-11-07 |
| D-26 | Host the relay on the owner's own server at home; move to a VPS if the app grows | No hosting cost while the app is small; the app reaches the relay by domain name, so a move needs no app update | 2026-11-07 |
| D-27 | The relay lives in this workspace as `crates/relay`                      | Shares `core`'s types and provider code; one gate, and one change updates both sides     | 2026-11-07 |
| D-28 | TVmaze for anime now; AniDB, through the relay, when more is needed      | AniDB has an API, and its strict limits and registered client suit a relay that caches   | 2026-11-07 |
| D-09 | Open Library for books, called directly; Google Books through the relay only if results are poor | No key, and enough coverage to start | 2026-11-07 |
| D-12 | Saved items keep their source data. Store each item's source ID, keep the user's own fields separate, and refresh TMDB data before it is six months old. Saved IGDB data follows IGDB's FAQ | Works offline, as a planner should; the relay's cache keeps to the stricter limits | 2026-11-07 |
| D-13 | The system font, Segoe UI on Windows                                      | Nothing to ship, and it looks native; easy to revisit once the screens exist              | 2026-11-07 |
| D-14 | Settings, including the theme, live in a `settings` table in the database; user API keys do not | One file to back up, using the existing migrations. Keys belong in the OS credential store, which needs its own dependency approval | 2026-11-07 |
| D-15 | A list view first, and a grid once covers work                           | Compact suits long planning lists, and covers are not built yet                          | 2026-11-07 |
| D-16 | `cargo-packager`, producing an NSIS `.exe` installer                     | One tool, with room for an updater. Code signing is a later decision                     | 2026-11-07 |
| D-18 | A second launch brings the open window to the front, using `interprocess` | What users expect, and two copies writing one SQLite file risk lock errors               | 2026-11-07 |
| D-21 | Open Library's User-Agent names the app and its repo, with no email      | The limit is per IP address, so 1 request per second per user is enough for a search that waits for typing to stop | 2026-11-07 |
| D-29 | The data folder is `%APPDATA%\loregalia`; an old `com.manu.loregalia` folder is renamed at startup | A clean path the owner can find, without losing anyone's library | 2026-11-11 |
| D-30 | An optional portable zip keeps its data beside the `.exe`, marked by a `portable` file | Runs from a USB stick or a synced folder, with no installer | 2026-11-11 |
| D-32 | User API keys live in Windows Credential Manager, through `keyring-core` and `windows-native-keyring-store`; an old `api-keys.json` is moved in at startup | Keys are secrets, and a plain-text file beside the library is easy to copy or sync by accident | 2026-11-13 |
| D-33 | IGDB data may be stored and served beyond 24 hours. The relay keeps searches for 7 days and game details for 30 | IGDB's FAQ (questions 3 and 5) prefers that apps store and serve its data, which is the written permission the Twitch agreement's storage clause allows. Details stay within 30 days because IGDB removes a replaced image after 30 days | 2026-11-14 |
| D-34 | Covers are cached on disk, capped at 200 MB, oldest first; TMDB covers are refreshed after 150 days | About 25 KB a cover; covers show offline and are not downloaded on every launch, within each source's terms | 2026-11-14 |
| D-35 | Items keep details from their source: synopsis, length, genres, creator and full release date, in English, with no ratings. They live in the source data, so no migration is needed, and never replace what the user typed | PRODUCT.md promises an item's details, and choosing what is next needs its length and what it is about | 2026-11-24 |
| D-36 | Missing details fill in by themselves, one item every 4 seconds, newest first. Three failures in a row or one rate limit stop it until the next launch or the next item added from a search | 15 requests a minute leaves half of the relay's limit for searching, and one slow source does not stop the rest | 2026-11-24 |
| D-37 | Covers load only over HTTPS, and only from the four sources' image servers | A compromised source or relay cannot make the app call other addresses. Redirects must stay on HTTPS; Open Library redirects to archive.org | 2026-11-24 |
| D-38 | A connection that is not made within 3 seconds, or is dropped, is tried once more. A server that is only slow to answer is not asked twice. Covers are tried again after 5 and 20 seconds | Home connections stall: on 2026-11-24 plain requests to IGDB and TMDB took 3 to 12 seconds at random, almost always while connecting | 2026-11-24 |
| D-39 | Rows and tiles have fixed heights, and only those near the window are drawn. The focused one is always drawn | Frame time no longer depends on library size: 3,000 items took 255 ms a frame and now take 2 to 6. Fixed heights make the visible range arithmetic, and an undrawn focused row would leave the keyboard shortcuts with nowhere to go | 2026-11-25 |
| D-40 | Settings saves a backup (a verified copy of the database), JSON or CSV. JSON and CSV hold the user's own data and source IDs, not synopses, lengths or covers. CSV cells that could run as a formula get a leading apostrophe | A local-first app should make leaving easy. Source content can be fetched again by its ID, and TMDB limits how long copies may be kept | 2026-11-25 |
| D-41 | Pick for me suggests only what is planned or on hold and already released. A movie must fit the time with 10 minutes of grace, a show needs room for one episode, and books and games always fit. Lists, time on hold, how long something has waited and some chance decide the order, and every suggestion says why. Nothing is learned or stored | Choosing what is next is the product's purpose, and it needs no account, history or outside service | 2026-11-25 |
| D-42 | Coming soon holds unreleased items, and new seasons of shows not dropped, soonest first, plus what came out in the last 14 days. What can still change is refreshed weekly: unreleased movies and games, and shows that have not ended. No notifications | Dates move, and a planner should say when something is out without interrupting. Episodes stay untracked: only the first episode of a season counts | 2026-11-25 |
| D-43 | At most once a day, at launch, the app asks GitHub for the latest release and shows a link when it is newer. On by default, with a switch in Settings. The app never downloads or installs an update. The link is fixed in the app, never taken from the answer | Fixes must reach people, but an updater is risky code to ship before the app is signed. A fixed link means a bad answer can only show a wrong number | 2026-11-25 |
| D-44 | Settings restores a backup, after showing what it holds. It replaces the library in one transaction, and settings and API keys stay. A copy of the replaced library is always kept in the data folder and never deleted by the app. A library too damaged to open is renamed, and the backup takes its place | Copying files by hand is easy to get wrong, and a restore must be undoable. Settings belong to the computer: an old backup must not turn the update check back on | 2026-11-25 |
| D-45 | The C runtime is linked into `loregalia.exe`, and the release fails if it needs the Visual C++ runtime. The winget package is `ManusolJ.Loregalia`, installed silently for the current user. The installer keeps "Manu" as publisher, which the manifest maps | A clean Windows may not have `VCRUNTIME140.dll`, and the app would not start there. The installer keeps the install folder under the publisher's name, so renaming it would lose a custom folder on upgrade | 2026-11-25 |
| D-46 | The website is one static page at `loregalia.app`, in its own repository `ManusolJ/loregalia-web`, served by GitHub Pages. The installer and the winget listing name it as the homepage. Its buttons download `loregalia-setup.exe` and `loregalia-portable.zip`, copies that every release adds under fixed names, through `releases/latest/download/` | The domain keeps links working if the hosting changes. A separate repository keeps the site out of the Rust gate and the release workflow | 2026-11-26 |
